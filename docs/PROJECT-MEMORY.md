## 1. What Dreams is

- A 2D top-down farming/life/adventure game in **Godot 4.5.1** (GDScript), portrait **270×480**, touch D-pad + A/B/MENU. Tom plays only on his **phone**, through the web build: https://excivious27.github.io/Dreams/ (every push to `main` deploys via GitHub Actions; the repo is public `Excivious27/Dreams`).
- Feel targets: **Stardew Valley** for controls/inventory/combat/menus/farm start; **Sun Haven** for big open regions with organic edges.
- Goal: a polished, Stardew-grade commercial release (Steam later). "100%" means polish, not just features.
- **Two story arcs**, chosen at new game (each save slot keeps its own):
  - **Penguins — "The Two Too Powerful Penguins"**: the Star Crystal lands on your farm; partners Pip-Pip (crown) and Nova (wizard hat); Catkins teaches the Meow Pow Wow; Merkitties at the lake; Cat-topia; Sanctuary system (pool, burrow, shrine). Money: crystals (◆).
  - **Gangsters**: you hide out on a farm under a fake name; M. writes letters; Sal (bearded man, bench by the town gate) is the mentor; the President and his collectors; Hideout town; crew recruits (Deuce, Mama Rosa…); Racket system (heat, bills, press, laundromat, training); the Marked (people with Gifts who never die, are befriended/recruited). Money: **cash ($)** everywhere. All-ages: guns OK, **no blood, gore, drugs, alcohol focus, prostitution or anything mature**. Characters look serious/cool/dark underworld-cyberpunk, ages ~15–30 (family members Grandma June and Dad stay older).
- Player family/heroes come from Tom's own pixel pack (man, woman, son, girl, dog) plus many generated heroes. The dog/pup is your companion (follows, fights, fetches, enters mines).

## 3. How the work happens (process)

**CONDUCT process: the single source is docs/HANDOFF.md "CONDUCT operating rules (current, 2026-11-20)".**

- **Rounds** of work, each ending with: check.sh green → push → bots/playtest → the **package** (see 6).
- **CONDUCT process (since 2026-11-19, Tom; CI-optimised 2026-11-19 20:18, target ~1.5 h all in):** 20 read/play-only auditors write findings to `/home/claude/wt/cN_reports/<id>.jsonl` (+ `<id>.done`; a restarted auditor continues, never redoes) → `python3 tools/conduct/cluster.py <dir> 6` drafts file-disjoint fix packages (each big shared file one owner) → 5-6 fix agents in parallel (targeted tests only, never check.sh/bots.sh, 60-75 min cap) → one merge + local smoke → **`bash tools/conduct/ci_run.sh <label> 3`** (GitHub Actions: check.sh in 6 shards + 20 bots; summary from branch `ci-results/<sha>/`; exit 0 pass / 1 fail / 3 no results → fall back to local) → fix → push → deploy; build the package while CI runs. Pipelining: the next CONDUCT's 14 focus auditors start on a snapshot of origin/main when the merge starts; its 4 regression + 1 performance + 1 inventory auditors after the merge is pushed. Heavy runs (full check.sh, bots.sh) never run locally. Every report carries a timing table (with effort per role and agents per effort). **Usage rules (Tom 22:49):** effort MEDIUM for focus auditors, fix agents and merges; LOW for regression/perf/inventory auditors (checklists), CI triage, package building (one subagent), art slicing, watchdog; code map per CONDUCT (tools/conduct/code_map.py -> /home/claude/wt/cN_map.md) in every brief; auditors reply one line; main chat reads cluster.py output and CI summary.txt only; watchdog 45-60 min while healthy. Quality check: a low-effort role that misses something goes back to medium (note it here).
- Big rounds use **sub-agents in git worktrees**: `/home/claude/wt/<id>` on branch `<round>/<id>`, heavy dirs (art/, audio/, reference/, build/, .godot) hardlinked from the main checkout (`tools/conduct/mkwt.sh <id> <branch>`; copy tools/conduct/* to /home/claude/wt/ first; agent brief docs/CONDUCT-BRIEF.md). Agents commit locally, never push; the main chat merges, runs check.sh, pushes. Rules every agent gets: never write a hardlinked file in place (rm then write), wrap every godot run in `flock /tmp/godot.lock`, fresh `XDG_DATA_HOME`, run full check.sh once at the end.
- Merge lessons: JSON conflicts → union merge (keep both sides' keys/list items); never auto-resolve shell/code files with a "keep both lines" script (it dropped `fi` lines in check.sh once); new `class_name` scripts need `godot --headless --import` before tests see them; `.godot` class cache is shared through the hardlinks.
- **Watchdog:** while agents/bots run, check all of them every 30 minutes (send_later) and resume/restart anything stopped or stuck (Tom, 2026-11-19).
- The machine has 2 CPUs; 20 agents queue on the godot lock. Expect a full check.sh to take 10–30 min under load.
- `tools/gang_play_test.gd` has wall-clock waits that can flake under load (pup dig); re-run before assuming a real failure.
